# M1-03 ゴールドセットと評価（lawvis・JLaw との突き合わせ）

## 目的

抽出器の精度を、抽出器を作る担当とは独立に測る。結果は M5 で「手法とデータ」のページに公開し、信頼性で lawvis（評価なし）と JLaw-CiteGraph（自己評価のみ）を超える根拠にする。

## 並行性と依存

- 前提: `00-data-contract.md`、`verified-facts.md`、`README.md`。
- 前半（外部データの準備、注釈の手引き、評価スクリプト）は、すぐに着手できる。
- 後半（文の抽出と注釈）は `data/corpus/{snapshotId}/` ができてから（m1-01 が知らせる）。
- 評価の実行は `data/refs/{snapshotId}/` ができてから（m1-02）。
- 独立性: 抽出器の規則（m1-02 の仕様とコード）を注釈の前に読まない。注釈が終わるまで、抽出器の出力も見ない。

## 出力（`data/eval/{snapshotId}/`）

- `gold/guideline.md`: 注釈の手引き（下の「注釈の決まり」を具体例つきで書いたもの）。
- `gold/sentences.jsonl`: `{ gid, lawId, pid, sent, part, text, articleText, stratum }`。`articleText` は注釈のときに見た条全体の本文（略称の定義を見るため）。
- `gold/annotations.jsonl`: `{ gid, annotator, refs: [{ start, end, mention, tgtLaw | null, tgtStatus, tgtPid | null, tgtEnd | null, kind, yomikae }] }`。1文につき1行、注釈者ごと。
- `gold/adjudicated.jsonl`: 二重注釈の不一致を裁定したあとの最終版（同じ形、`annotator: "final"`）。
- `external/lawvis-pairs.csv`: `src_law_id,tgt_law_id`（50分野の和集合、重複なし）。
- `external/jlaw-pairs.csv`: `src_law_id,tgt_law_id,n_citations`（JLaw の `cites_law_to_law.csv` から）。
- `external/jlaw-precision-sample.csv`: JLaw の `eval/precision_sample.csv` の写し。公開版は `label_O_X` が400行すべて空（注釈用のひな形）で、JLaw の自己評価の値はこのファイルから再現できない。
- `external/jlaw-precision-labeled.csv`: 上の400行に、この担当が付けたラベルを足したもの。列は元の列に `our_label`（`O`・`X`・`?`）、`correct_law_id`（`X` のとき正しい lawId。法令への言及でないか引けなければ空）、`note` を足す。
- `external/jlaw-recall-gold-sample.csv`: JLaw の `eval/recall_gold_sample.csv` の写し。これも `missed_count` が空のひな形なので、指標には使わない（件数だけ記録する）。
- `report.json`: 下の指標。`report.md`: 人が読む要約と誤りの分類。
- コード: `pipeline/src/eval/`。コマンド `npm run eval -- --snapshot {snapshotId}`。

## 外部データの取り方

- lawvis: `https://www.lawvis.info/data/graphs/{key}.json` を50分野（key は `verified-facts.md`）。`User-Agent` ヘッダを付け、1秒に2件まで。エッジは `[src, tgt]` が「参照する側 → 参照される側」。和集合は 8,685 法令・113,641 ペアになるはず。社内の比較にだけ使い、生のデータは公開しない（公開するのは件数と分類だけ）。
- JLaw: `https://raw.githubusercontent.com/yabooung/jp-law-citation-graph/main/data/cites_law_to_law.csv` と `…/eval/precision_sample.csv`、`…/eval/recall_gold_sample.csv`。データは CC BY 4.0。公開するときは出典を書く。

## ゴールドセットの作り方

- 大きさ: 300文。種固定（`mulberry32(20261008)`）で抽出する。
- 層: 法律120、政令70、府省令80、規則15、勅令・その他15。そのうち附則系を40文以上含める。
- 難しい文の下限（層と重なってよい）: 「同法」「同条」を含む40、「以下「…」という」を含む30、「から…まで」30、「準用する」40、「読み替え」20、「の例による」20、「適用しない」15、「政令で定める」を含む施行令の文（「法第…条の政令で定める」）25、参照を含まない文20（誤検出を測るため）。
- 1文だけでなく、その文の条の全体（`articleText`）と、その法令の中の略称の定義（「以下「…」という」を含む文）を見て注釈する。必要なら e-Gov の法令ページで前後を確かめる。
- 二重注釈: 300文のうち100文（種固定で選ぶ）を、別の注釈者がもう1度、最初の注釈を見ずに注釈する。2人目は coordinator が別のモデルで起動する（この担当は、2人目に渡す `gold/second-pass-input.jsonl` を用意する）。不一致は、この担当が根拠を書いて裁定する（`adjudicated.jsonl`）。
- 第2版: 手引きを直したうえで、c1 だけの200文と補充40文を2人が独立に注釈し直して裁定する。2人目用は `gold/second-pass-v2-input.jsonl`（文と条本文だけ）。裁定済みの100文は、手引きの直しに当たる箇所だけ直す。本評価は第2版のゴールドと抽出器の新しい `manifest.json` がそろってから行う。

## 注釈の決まり

詳細と例は `gold/guideline.md`（第2.1版）。要約:

- 1つの参照 = 法令名・法令番号・条項をまとめた1つの言及（法令番号だけに分けない）。言及は法令名（略称を含む）から始める。限定の括弧書きは含めない。範囲（AからBまで）と枝番の条は分けない。語（「大学」など）や長い名前の一部、様式の号、「次の表」「同表」は参照にしない。
- 自分を指す語だけの言及（「この法律」「この政令」「この省令」「この府令」「この規則」「この命令」「本法」で条項が続かないもの）は参照にしない。改正法由来の附則の中のものも同じ。条項が続けば1つの参照（「この法律第三条」は `self`、`m.a3`）。
- 並列は分ける（「民法第一条、第二条及び第三条」は3つ）。括弧書きや「本文」「の規定」をはさんでも並列は続き、後ろの条項は前の参照の法令を引き継ぐ。範囲は1つ（「第三条から第五条まで」「第三条乃至第五条」は1つで、終わりを `tgtEnd` に書く）。
- 括弧の中の手がかりのない号・項は直前の条項のもの。ただし「（第M項において「X」という。）」「（次号及び第三号において同じ。）」のような範囲を示すものは今の条のもの。
- 「同条」「同項」「同号」は直前に出た条項（他法令でもよい）を指す。今いる条・項そのものではない。先行詞が他法令なら、その法令への参照（`self` にしない）。「この条」「本条」は今いる条。
- 「同法」の先行詞は、その語より前に出た法令だけ。
- 法令番号と「以下「…」という」が同じ括弧にあるとき、言及は法令名と番号まで。番号のない「X法（以下「法」という。）第A条」も X法 と 第A条 の2件。略称の範囲を示す条項は今の文書の条。lawId が確証できない題名は `unknown`（コーパスの廃止一覧は増やさない）。表のイロハ細分は pid が取れなければ号まで。読替えの印は読み替えられる側にだけ付ける。
- 改正附則: 施行期日の号の「第A条の規定（Y法…を除く。）並びに第B条」の第B条は改正法自身の条。「X法の一部を改正する法律（…）」の後の「同法」は改正法。「新X法」「旧X法」「改正前のX法」は X。「新令」がこの政令自身の定義なら `self`。「Y法第一条の規定による改正前のX法」の X 側は「改正前のX法」から。「X法附則」だけ（条なし）は `tgtPid: null`。
- 第2.1版: レビューで手引きと食い違った final を手引きどおりに直す。本評価の判定は第2.1版で行う。
- 相対参照の pid は必ず埋める。「前条」「次条」は条番号で数える（抄で載っていなくても）。枝番の条は数に入れる。
- 参照先は、施行中の法令なら lawId、廃止法令なら lawId と `repealed`、改正法なら `amendingLaw`（**lawId は必ずなし**）、自分自身なら自分の lawId と `self`。
- 条項は pid（00 の文法）で書く。条までしか分からなければ条まで。
- 種類は 00 の8種から1つ。判断に迷ったら `cite` にして `guideline.md` に例として残す。
- カギ括弧の中（定義語、改正後の文言、読替えの文言）の条項は参照にしない。

## 指標（`report.json`）

- 照合の仕方（主）: 予測とゴールドの参照は、文が同じで、範囲が半分以上重なれば対応づける（1対1、重なりの大きい順に貪欲に）。
- 照合の仕方（副・緩い照合）: 範囲の書き方を揃えたうえで、言及の始まりが同じか、一方の範囲が他方を含めば組にする。他法令・条単位・相対参照について、主の指標とは別に出す。
- 数えない予測: 手引きで付けないと決めた表現は、予測にあっても正解にも誤りにも数えない。判定は予測の `mention` の文字列だけで行う（`^(この(法律|政令|省令|府令|規則|命令)|本法)$`、および `^(各号|ただし書|但し書|本文|前段|後段|次の表|同表)$`）。抽出器の `rule` と `flags` は読まない。
- 他法令の法令単位: ゴールドの `tgtStatus` が `current` または `repealed` で、`tgtLaw` が自分でないもの。`amendingLaw` と `unknown` は、`tgtLaw` が付いていても他法令に数えない。法令が一致すれば正解。適合率・再現率・F値。文単位のブートストラップ（種固定、1,000回）による95%区間を F1・P・R に添える。
- 条単位: 法令と、`tgtPid` の条の部分（`m.a3` まで）が一致すれば正解。こちらも文単位のブートストラップ95%区間を添える。
- 法令内の参照: ゴールドの `tgtStatus` が `self` で `tgtPid` があるものと、予測の `tgtLaw` が参照元と同じで `tgtPid` があるもの。2つの値を出す。
  - 全体: 上のすべて。
  - 相対参照: ゴールドの `mention` が `^(前|次)(条|項|号)|^前各(項|号)|^(前|次)[二三四五六七八九十]+(条|項|号)|^同(条|項|号)|^本(条|項)|^この(条|項|号)` に当たるもの。予測側も同じ式を `mention` に当てて選ぶ。
  - 相対参照は2本に分ける。組になって法令が合うもの（`lawOk`）と、そのうえで pid も合うもの（`pidOk`）。組になって pid だけが違うものは、FN と FP の両方に数えない（`lawOk` では正解、`pidOk` ではゴールド側の取りこぼしだけ）。m1-02 の受け入れに出す主の値は `lawOk`。
  - 300文の中の相対参照は「同条」「前項」「同項」「前条」「この条」「この項」に偏る。そこで「前号」「次条」「次項」「前各項」「前各号」「前二条」などを含む文を種固定で40文足し、`gold/supplement-relative.jsonl`（`sentences.jsonl` と `annotations.jsonl` を合わせた形、`stratum: "relative-extra"`）に注釈する。第2版ではこの40文も二重注釈する。相対参照の値は300文の分と足した分を合わせて出し、語ごとの件数と、文単位のブートストラップ（種固定、1,000回）による95%区間も添える。
  - `pidOk` の判定: `tgtPid` と `tgtEnd` がどちらも一致。ゴールドが予測より粗い（ゴールドが条まで、予測が項まで）ときは、予測の pid がゴールドの pid で始まれば正解。予測のほうが粗いときは誤り。条まで丸めて一致する割合も別に出す。
- 種類: 対応づいて法令も合っている参照のうち、種類が一致する割合。種類ごとの混同行列も出す。
- 二重注釈の一致: 100文での参照単位の一致率と、種類の Cohen の κ。第2版の200+40文は、2人目が揃い裁定したあとに同じ値を出す。
- JLaw のサンプル: 公開版にラベルがないので、この担当が400行にラベルを付け（`jlaw-precision-labeled.csv`）、同じ400件で JLaw と我々を比べる。
  - ラベルの付け方: `ctx_before`・`ctx_hit`・`ctx_after` と、必要ならコーパスの本文を見て、`ctx_hit` が指す法令が `resolved_id` と同じなら `O`、違えば `X` で `correct_law_id` に正しい lawId を書く。「改正前の」「旧」の付く言及も、法令が同じなら `O`（版の違いは問わない）。法令への言及でない、または判断できないものは `?`。抽出器の出力を見る前に付け終える。
  - 対応づけ: `source_id` の法令の本文から、`ctx_hit` を含み `ctx_before` の末尾と続く箇所を探し、その範囲と半分以上重なる我々の参照を採る。本文の版の違いで見つからない行は「対応なし」として数だけ出す。
  - 出す値: `?` を除いた行での JLaw の適合率（`O` の割合）。対応がついた行で、我々が正しい法令（`O` なら `resolved_id`、`X` なら `correct_law_id`）に解決した割合。我々が参照を出さなかった行の割合。`X` の行のうち我々が正しく解いた数。
  - ラベルの確かさ: 種固定で選んだ80行を2人目の注釈者がもう1度ラベルし、一致率を `report.json` に書く（2人目の起動は coordinator に頼む）。
- 法令ペアの突き合わせ（lawvis、JLaw のそれぞれと）: 我々のペア（本則系、`amend` を除く、施行中どうし）と相手のペアの、共通、我々だけ、相手だけの数。比べる範囲は両方に法令がある範囲に限る。
- 差の分類: 「我々だけ」と「相手だけ」から50ペアずつ（種固定）を取り、本文を見て、我々の取りこぼし・我々の誤り・相手の誤り・定義の違い（附則を含めるかどうか、改正法の題名の中の法令、カギ括弧の中の読替え後の文言など）・判断できない、のどれかに分ける。改正法の題名の中の法令（「内閣法の一部を改正する法律」の「内閣法」）とカギ括弧の中の読替え後の文言は「取りこぼし」ではなく「定義の違い」とする。

## 受け入れ条件

- 300文の注釈、100文の二重注釈と裁定がそろっている。
- `npm run eval` が `report.json` と `report.md` を作る。抽出器の出力が変われば、数分で作り直せる。
- 二重注釈の参照単位の一致率が0.90以上（下回るなら手引きを直して、不一致の多い文を注釈し直す）。
- lawvis と JLaw の比較が、差の分類まで含めてそろっている。
- JLaw の400行のラベルと、その上での JLaw と我々の比較がそろっている。
- 評価は `data/refs/{snapshotId}/manifest.json` があるときだけ動く（なければ「抽出が未完成」と出して止まる）。
- `report.md` の最初の段落だけで、精度と比較の結論が分かる。

## テスト方法

- 照合と指標の計算に単体テストを書く（手で作った予測とゴールドの組で、適合率・再現率が手計算と一致すること）。
- 外部データの件数の検算（lawvis 8,685 法令・113,641 ペア、JLaw 70,577 行）。日付が違えば差を書く。
