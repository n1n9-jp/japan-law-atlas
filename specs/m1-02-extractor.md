# M1-02 参照抽出器 v1

## 目的

コーパスのすべての文から、法令と条項への参照を取り出し、参照先の法令・条項と種類（8種）を決める。他法令への参照の精度で、公開されている先行例（北野・天笠 NLP2026 の F値0.935、JLaw-CiteGraph の他法令解決 82.2%）をはっきり上回ることを狙う。決定的な規則だけで作り、LLM は使わない。

## 並行性と依存

- 前提: `00-data-contract.md`、`verified-facts.md`、`README.md`。
- すぐに着手できる。最初はコーパスなしで、規則と単体テストを、この仕様の例文と e-Gov API から手で取った文で作る。
- `data/corpus/{snapshotId}/` ができたら（m1-01 が知らせる）、全件で動かす。
- 評価（m1-03）とは別の担当が並行して進める。ゴールドセットの中身は見ない（評価の独立性のため）。m1-03 が `data/eval/` に評価スクリプトを置いたら、それを実行して結果を見るのはよい。
- 出力の形は 00 で固定されている。m2-01（グラフ）は、この出力の最初の全件版ができたら着手できる（精度が目標に届く前でよい）。

## 入力と出力

- 入力: `data/corpus/{snapshotId}/`（`laws.json`、`repealed.json`、`text-*.jsonl.gz`）。JLaw の略称辞書 `jp_abbrev_kit.json` と `jp_law_aliases.json`（Apache-2.0。`pipeline/vendor/jlawcite/` にライセンス文と出典を添えて置く）。
- 出力: `data/refs/{snapshotId}/` の `refs-*.jsonl.gz`、`abbrevs.jsonl.gz`、`law-features.jsonl`、`stats.json`、`unresolved-sample.jsonl`（形式は 00）と `manifest.json`（`{ snapshotId, corpusSha256, createdAt, files: [{ path, bytes, sha256 }] }`。`corpusSha256` はコーパスの `manifest.json` の sha256）。
- 書き出しの手順: いったん `/tmp/hourei-refs/{snapshotId}/` に全部書き、store へ写したあと、写した先のファイルの大きさと sha256 を読み直して確かめる。合わないもの・写せなかったものが1つでもあれば終了コード 1 で止まる。`manifest.json` は確かめ終わってから最後に書く。読む側（m1-03、m2-01）は `manifest.json` がなければ未完成として扱う。書き直すときは、最初に古い `manifest.json` を消す。
- コード: `pipeline/src/extract/`。コマンド `npm run extract -- --snapshot {snapshotId}`。`--law {lawId}` で1法令だけ動かし、結果を人が読める形で表示するデバッグ用の出力も付ける。

## 処理の流れ

法令ごとに、文書順に文を処理する。法令をまたいで状態を持たない。法令の中では「定義された略称」と「直前に出た参照」を状態として持つ。

### 1. 辞書を作る（全法令で1回）

- 法令番号の辞書: `numNorm` → `lawId[]`。施行中と廃止の両方（`laws.json` と `repealed.json`）。
- 法令名の辞書: 現在の法令名、`oldTitles`、e-Gov の略称（`abbrevs`）、JLaw の略称辞書 → `lawId`。同じ名前が複数の法令を指すときは、施行中を優先し、それでも複数なら辞書から外して `stats.json` に記録する。
- 辞書に入れる名前の条件: `oldTitles` は1件を1つの題名として扱い、「、」などで分けない（分けると「監督」のような断片ができ、無関係な文に当たる）。どの出どころの名前も、3文字以上で、末尾が `法|法律|令|政令|勅令|規則|省令|府令|規程|細則|条約|協定|憲法|布告|達` のどれかであるものだけを入れる。外した名前の数は `stats.json` に出す。
- 法令名の照合は、自前のトライ木で最長一致にする（20,000語程度）。正規表現の大きな選択肢は使わない。

### 2. 文の前処理

- カギ括弧の伏せ字: 「」（入れ子と『』を含む）の中身を、同じ長さの記号（`\u0000`）で伏せた照合用の文字列を作る。参照はカギ括弧の外だけで探す（定義語や改正後の文言の中の「第三条」を拾わないため）。略称の定義（下の 3）だけは伏せる前の文字列を見る。
- 丸括弧の深さを文字ごとに計算しておく（法令番号の括弧と、括弧書きの中の定義の判定に使う）。
- カタカナ書きの文（ひらがなを1文字も含まない文）では、カタカナを送り仮名・助詞として扱う。法令名の左右の境界（L2・L5）で、カタカナを漢字と同じ「語の続き」と見なさない（「…ニ於テX法第A条」「…ヨリX法施行令第A条」の X法、X法施行令を採る）。

### 3. 略称の定義を拾う

- 形: `（…。以下(この(条|項|号|章|節|款|目)において|本(条|項)において)?(単に)?「X」という。）` および括弧の外の `以下(…において)?「X」という。`
- 範囲を示す語で始まる形も拾う: `（(…。)?(同|次|前|第N)(条|項|号)((及び|並びに|、)(同|次|前|第N)?(条|項|号))*において(単に)?「X」という。）`（「（同項において「X」という。）」「（第四項及び第五項において「X」という。）」「（次条において「X」という。）」）。
- 定義の文: `「X」とは、Y(を|の)いう` または `「X」とは、Y(をいい|をいう。)`（定義の条の号「十　「X規則」とは、Y規則（…号）をいう。」を含む）。Y が法令の参照（法令名、法令番号つき、略称、改正前後の前置きつき）なら X は Y の法令の略称。Y が法令でなければ（「「事業者」とは、…をいう。」）法令の略称にしない。
- 法令番号の括弧の中の定義（「Y法（昭和…年…第…号。以下「X」という。）」「Y法等の一部を改正する法律（平成…年法律第…号。以下「X改正法」という。）」）は、Y が辞書で引けても引けなくても必ず記録する（引けなければ `amendingLaw` か `unknown` として記録し、後の「X第A条」「X附則第A条」を同じ行き先にする）。定義の括弧を見つけたのに記録しなかった数を、理由別に `stats.json` に出す。
- 何の略称か: 定義の括弧の直前で終わる参照（法令名、法令番号つきの法令、または条項）だけを対象にする。括弧と参照の間に別の語があれば対象なし。対象が法令なら「法令の略称」、条項なら「条項の略称」（例: 「第五条第一項の許可（以下「許可」という。）」は法令の略称ではないので捨てる）。
- 法令の略称にする条件: X の末尾が辞書の条件（上の 1）と同じ法令の種類の語であること（「法」「令」「新法」「旧令」「措置法」「改正法」「旧X法」はよい）。末尾が合わないもの（「許可」「対象事業者」「特定設備等」「〇〇地域」のような語）は、対象が何であっても法令の略称にしない。
- 改正の前後を指す略称: 対象が「…の規定による改正前の X」「…による改正後の X」「改正前の X」「改正後の X」なら、略称は X を指す（X がこの法令自身なら `self`）。「…による改正」を作った改正法を指すのではない。対象が「X の一部を改正する法律（…号）」のように改正法そのものなら、その改正法（辞書になければ `amendingLaw`）。
- 定義の括弧をはさむ法令名と条項は2件: 「X法（以下「法」という。）第A条第B項」「X法（昭和…号。以下「法」という。）第A条」は、1件目を法令（`mention` は X法、法令番号があれば番号の終わりまで。定義と閉じ括弧は含めない。`tgtPid: null`）、2件目を閉じ括弧の直後の条項（`mention` は「第A条第B項」。法令は1件目を引き継ぐ。`rule` は1件目と同じ、`flags` に `enumCarry`）にする。括弧の中が法令番号だけ（「X法（昭和…号）第A条」）のときは、今までどおり名前から条項の終わりまでを1件にする。
- 有効範囲: 「以下」だけなら、その文から同じ部の終わりまで。ただし制定文と本則で定義したもの（定義の文を含む）は、本則と制定時の附則（`s1`）と別表など（`t<k>`）にも効く（施行令の附則や別表に出る「法第A条」「規則第A条」の「法」「規則」は、本則で定義したものを指す）。「この条において」は条の終わりまで、「この項」は項、「この号」は号、「この章」「この節」「この款」「この目」はその単位の終わりまで（`toc` と `articles` で範囲を決める）。「同項において」「第N項において」「次条において」は、その語が指す今の法令の単位まで。その単位が今の法令の中で決められないとき（「同項」の先行詞が他の法令の項のとき）は、定義のある文から今の条の終わりまで（条のない附則では今の項の終わりまで）。定義の文の範囲は、その文がある部（本則の定義の条なら上の本則と同じ範囲）。
- 本文の定義は辞書より先: 有効範囲の中に本文の定義がある語は、e-Gov・JLaw の略称辞書で引かない。範囲の外でも、同じ法令のどこかで本文で定義された語（「措置法」「規則」など）は、JLaw 由来の略称辞書では引かない。
- 法令の中の予備の定義（範囲の外の定義を最後の手がかりにする）: 有効範囲の中に定義がなく、辞書でも引けない略称らしい語（末尾が上の 1 の法令の種類の語で、後ろに「第…条」「附則第」「別表」「の規定」が続くもの）は、同じ法令の別の場所の定義を使う。順に、(1) 同じ語の定義、(2) 前置き「新」「旧」「改正前」「改正後」を外した語幹が同じ定義（「新X規則」の定義があれば「旧X規則」も X規則）。複数の行き先に割れるときは使わない。`rule: 'L2-abbrev-fallback'`、信頼度 0.7。改正附則が「抄」で、略称を定義した条が本文に載っていないときのためのもの。
- 引けない略称らしい語の後の条項: 上でも引けないときは、語と条項を1つの参照にして `tgtLaw: null`、`tgtStatus: 'unknown'` にする（後ろの条項だけを改正法や自分の法令の条にしない）。
- 改正法由来の附則（`supplAmend`）の中で定義された「旧法」「新法」など、対象がこの法令自身なら `self` として記録する。

### 4. 参照を見つける規則（優先順。同じ範囲に複数当たれば前の規則を採る）

- `L1-number` 法令番号つき: `名前（元号…年…第…号` の形。番号を `numNorm` に直して辞書を引く。名前の始まりは、引いた法令の法令名か旧法令名が直前の文字列の末尾と一致すればそこ。一致しなければ、直前の区切り（、。「」（）、全角空白、文の始め、「及び」「又は」「並びに」「若しくは」の後）まで戻る。番号が辞書にない場合、名前が「一部を改正する」「改正する(法律|政令|省令|規則)」「整備(等)?に関する(法律|政令|省令)」「廃止する(法律|政令)」を含めば `tgtStatus: 'amendingLaw'`、そうでなければ `unknown`。
- `L2-abbrev` 本文で定義された略称: 有効範囲の中で、略称 X の後に「第…条」「附則第」「別表」「の規定」「に規定する」「に定める」「施行令」「の施行」「の適用」「による」「により」「に基づ」「の一部を」「、」「及び」「又は」「並びに」「若しくは」「（」が来るもの。「法」「令」「規則」のような1〜2文字の略称も同じで、文の始めに来るもの（「法の規定により…」）も採る。X の直前の文字が漢字かカタカナなら、長い語の一部なので当てない。ただし直前が「新」「旧」「改正前の」「改正後の」で、その前置きをつけた語（「新令」）が別に定義されていなければ、X と同じ法令として当て、`mention` に前置きを含める（L5 の前置きと同じ）。定義されていればその定義を使う。
- `L3-anaphora` 前の参照を指す語: 「同法」「同令」「同規則」「同省令」「同府令」は、直前に出た他法令の参照の法令を指す。探す順は、同じ文の中でその語より前（近い順）、なければ同じ条の中の前の文（条が変わったら忘れる）。種類が合わない候補は飛ばして、さらに前を見る。合う種類は、「同法」が `Act`・`Constitution`・`Misc`、「同令」が `CabinetOrder`・`ImperialOrder`・`MinisterialOrdinance`・`Misc`、「同規則」が `Rule`・`MinisterialOrdinance`、「同省令」「同府令」が `MinisterialOrdinance`。候補には改正法の参照（`amendingLaw`）も含め、その種類は題名の末尾（法律→法、政令→令、省令・府令→省令、規則→規則）で決める。改正法に当たったら `tgtLaw: null`、`tgtStatus: 'amendingLaw'`。見つからなければ未解決（`unknown`）で `rule: 'L3-anaphora-miss'`。法令番号の括弧の中の「同法」「同令」（「X法（平成…年法律第…号。同法第A条に規定する…）」）は、その括弧で番号を示している法令を指す（括弧の前の、別の法令の参照ではない）。
  - 「同条」「同項」「同号」は、同じ文の中でその語より前に出た条項の参照のうち一番近いもの（なければ同じ条の前の文の最後の条項の参照）の、条・項・号を指す。その参照が他の法令なら `tgtLaw` もそれを引き継ぐ（法令内の参照にしない。`relative` のフラグも立てない）。今いる条・項・号そのものを指すことはない。「同項」の先行詞に項がなければ（条だけの参照）、その条の第一項にはせず条までにする。
  - 先行詞の候補は、その文でそれまでに出した条項の参照すべて。括弧の中の参照（「X法第A条（Y法第B条に規定する…及び同条第三項に規定する…を含む。）」の「同条」は、括弧の中の Y法第B条）、連鎖で法令を引き継いだ参照（「法第A条第二項又は第B条第一項の…及び同条第三項」の「同条」は法の第B条）、それ自身が「同条」「同項」「同法…」で解決された参照（「法第A条第二項…同項第一号…同条第四項…同項」は全部 法の第A条）、法令番号の括弧の中の参照も含める。候補には、解決し終わった `tgtLaw` と `tgtPid` を使う。範囲を示す条項（上の 6 の「有効範囲の括弧」）と、法令単位の参照（`tgtPid: null`）は候補にしない。
  - 「同表」は表の参照だけを先行詞にする: 「次の表」「この表」「前項の表」「別表第N」「X第A条第B項の表」「X別表第N」。先行詞が自分の法令の表（「次の表」「この表」、自分の別表）なら `self`（`tgtPid` は表を含む条項、別表なら `t<k>`）。先行詞が他の法令の表なら、その法令とその条項。表の先行詞がなければ未解決（`unknown`）にし、表でない条項の参照（「X法第A条」）を先行詞にしない。「同表第N号」「同表の上欄」は1つの参照。
  - 後ろに続く条項は1つにまとめる: 「同条第四項」「同項第三号」「同号イ」「同表第七号」は1つの参照で、`tgtPid` は先行詞の pid に続きを足したもの（「法第A条の三第二項及び同条第五項」の「同条第五項」は法の `m.aA_3.p5`）。L7 の「前条第二項」「次項第一号」「前号イ」も同じく1つにまとめる。
- `L4-self` 自分を指す語: 「この法律」「この政令」「この省令」「この府令」「この規則」「この命令」「本法」は、その法令自身（`tgtStatus: 'self'`）。ただし `supplAmend` の中では改正法を指すので `tgtLaw: null`、`tgtStatus: 'amendingLaw'`。
- `L5-name` 法令名だけ: 名前の辞書で最長一致。
  - 左の境界: 前の文字が漢字かカタカナなら当てない。ただし直前が「条中」「項中」「号中」「表中」なら当てる（改正の指示「第一条中関税法第三条の改正規定」の形。改正附則の施行期日の号「第九十条中農林中央金庫法第四十六条の三の次に一条を加える改正規定」「第九十六条の規定（同条中商品先物取引法第十八条第二項の改正規定、…）」でも当てる。「同条中中小企業団体の組織に関する法律」のように「中」が2つ続く形も）。
  - 改正の前後を示す前置き: 名前の直前が「新」「旧」「改正前の」「改正後の」「改正前」「改正後」「廃止前の」（「第四条改正前」「…の規定による改正前の」を含む）なら、左の境界を満たすものとして扱い、`mention` に前置きを含める。`mention` は前置きの語（「改正前の」「新」など）から始める。前置きの前の「…の規定による」「第N条による」は含めない。参照先は名前の法令そのもの（「新X法第A条」は X法、「改正前のX規則第四号様式」はその規則、「廃止前のX法第A条」は X法で、廃止されていれば `repealed`）。名前がこの法令自身なら `self`。
  - 法令の中の位置の続き: 名前の後ろの「附則の規定」「附則」（条番号なし）、「第N編」「第N章」「第N節」「第N款」「第N目」（の連なり）、「第N号様式」「別記様式（第N号）」「様式第N」は、名前と1つの参照にまとめ、`tgtPid: null` と `lawLevelOnly` を立てる（「X法施行令第三編第二章」「X法附則の規定」）。右の境界の「附則第」「別表」と同じく、続きの語が漢字でも採る。
  - 右の境界: 後ろが「第…条」「附則第」「別表」「及び」「又は」「並びに」「若しくは」で始まるなら、それで採る（「第」「附」「別」「及」「又」「並」「若」が漢字でもよい。「…X法施行令、Y法施行令及びZ法施行令」の Y法施行令）。それ以外は、後の文字が漢字かカタカナなら当てない（長い名前の前半だけを拾わないため。「民法施行法」の「民法」、「〇〇法等の一部を改正する法律」の「〇〇法」）。
  - 琉球政府の立法: 名前の後ろの括弧が「（千九百…年立法第…号）」「（千九百…年布令第…号）」なら、日本の同名の法令ではない。名前と括弧を1つの参照にして `tgtLaw: null`、`tgtStatus: 'unknown'` にし、括弧の中の「第…号」を条項として読まない。「沖縄の」の直後の名前も同じく扱う。
  - 続き方: 現在の法令名か旧法令名で当たったものは、右の境界を満たせば続き方を問わず採る。e-Gov の略称で当たったものは、後ろに「第…条」「附則第」「別表」「の規定」「に規定する」「に定める」「による」「により」「に基づ」「の施行」「の適用」「の一部を」「を廃止する」「（」「、」「及び」「又は」「並びに」「若しくは」が続くものだけ採る。JLaw 由来の略称だけで当たったものは「第…条」が続く場合に限る。
  - 改正法の題名: 当たった名前の後ろが `^(等)?(の一部を改正する|を廃止する|の施行に伴う[^、。（）「」]*?|の施行等に伴う[^、。（）「」]*?)(法律|政令|省令|府令|規則|命令)` なら、それは別の法令（改正法・廃止法・整備法）の題名の一部。題名の終わりまでを `mention` と `rawName` にし、題名全体が辞書にあればその法令、なければ `tgtLaw: null`、`tgtStatus: 'amendingLaw'` にする（元の法令への参照にはしない）。「等」で始まる形は右の境界の例外としてここで扱う。
- `L6-provision` 条項だけ: 法令の手がかりがない「第…条」「第…項」「第…号」「附則第…条」「別表第…」。並列の連鎖（下の 6）の中なら前の法令を引き継ぐ（`enumCarry`）。それ以外はその法令自身への参照（法令内の参照）。ただし `supplAmend` の中の素の「第…条」（連鎖で引き継いだものを除く）は改正法の条なので `tgtLaw: null`、`tgtStatus: 'amendingLaw'`、`tgtPid` は改正法の中の pid（`m.a…`）を入れる。`supplAmend` の中の「附則第…条」は次の順に決める。
  - 素のもの（法令の手がかりも連鎖の引き継ぎもない）: この法令に `s<k>.a…`（今の文と同じ `k`）があればそれ。なければ改正法の附則の条なので `tgtLaw: null`、`tgtStatus: 'amendingLaw'`、`tgtPid: 's1.a…'`。e-Gov の改正附則は「抄」で一部の条しか載っていないことが多く、載っていない条は改正法の側にしかない。
  - 法令の手がかりが前にあるもの（法令番号つき、略称、法令名、「同法」、「新法」「旧令」など）と、連鎖で他の法令を引き継いだもの: その法令の制定時の附則 `s1.a…`。L2・L3・L5 は「附則第…条」が続くとき、「第…条」が続くときと同じように1つの参照にまとめる。参照先が改正法なら `s1.a…` をそのまま入れる。
  - 名前のない法令番号「昭和六十年法律第三十四号附則第五条」「平成十一年政令第二百六十二号第三条」は、番号を辞書で引いて `L1-number` として扱う（`mention` は元号から条項の終わりまで）。番号が辞書になければ `amendingLaw`。
  - 改正法（`amendingLaw`）の pid は、本則なら `m.a…`、附則なら `s1.a…`。改正法の本文はコーパスにないので存在確認はせず、`lawLevelOnly` も立てない。
- `L7-relative` 相対的な指定: 「前条」「次条」「前項」「次項」「前号」「次号」「前各項」「前各号」「前二条」「前三項」など「前N条/項/号」「本条」「本項」「この条」「この項」「この号」「各号」「ただし書」「前段」「後段」。今の文の位置から pid を計算する（「この条」「本条」は今の条、「この項」「本項」は今の項、「この号」は今の号。前N条は直前のN個の条で、範囲として `tgtPid`〜`tgtEnd` に入れる）。`relative` のフラグを立てる。「この条において」「この項において」のように略称の有効範囲を示す語も、参照として出す。
  - 条の数え方: 文書順の前後と条番号が食い違うとき（改正附則の「抄」で条が抜けているとき）は条番号で数える。今の条を第N条（枝番なし）として、文書順で直前の条の番号が N−1 でも「第N−1条の…」でもなければ、前条は第N−1条（`a{N-1}`）、前二条は第N−2条〜第N−1条、次条は第N+1条とする。枝番のある条（第N条のM）は文書順で数える（第四条の前二条は、第三条の二があれば第三条と第三条の二）。
  - 条番号で数えた pid がコーパスにない（抄で載っていない）ときも、pid は落とさずに残す（下の 5 の存在確認の例外）。項・号も同じ。

### 5. 条項の読み取り

- 文法: 条 `第N条(のN)*`、項 `第N項`、号 `第N号(のN)*`、号の細分 `イ`〜`ン`（イロハ順の番号に直す）、別表 `別表(第N)?`、別表の行 `別表第N(の)?K(の)?項`（「別表第三の一の項」。`t<k>.iK` と書き、行を号と同じに扱う）、附則 `附則第N条`（本則系と `suppl` からは制定時の附則 `s1`、`supplAmend` からは同じ改正附則 `s<k>`）。別表の行のあとの「同項」は、その行を指す。
- 号の細分は、号の直後に1文字だけ読む。2文字目のイロハは細分の続きにしない（細分の下は「（１）」で書かれる。カタカナ書きの古い法令の「第一号ホニ規定スル」の「ニ」は助詞）。イロハの直後がカタカナなら細分として読まない。
- イロハ1文字だけ（「第…号」が前にないもの）は参照の始まりにしない。並列の連鎖の中（「第一号イ及びロ」の「ロ」）でだけ読み、前の参照の号を引き継ぐ。
- 連鎖で条を引き継ぐときは、前の参照の部（`m`、`s<k>`、`t<k>`）をそのまま引き継ぐ。
- 続けて書かれたもの（「第三条の二第三項第一号イ」）は1つの pid にまとめる。
- 表の中の位置: 「旧X規則第A条第一項の表第一号イ」「同表第B号」のように、条項の後ろの「の表第N号」（とそのイロハ）は、前の条項の続きとして1つの参照にする。`tgtPid` は表を含む条項まで（表の号は pid にしない）。法令もその条項のものを引き継ぐ（自分の法令の第N号にしない）。
- 範囲: `A から B まで`、`A 乃至 B`。`tgtPid = A`、`tgtEnd = B`、`range` のフラグ。
- 条項の存在確認（他法令と自分の法令の両方）: 参照先の法令のコーパスに pid がなければ、`tgtPid` を条までに丸め、それもなければ `null` にして `lawLevelOnly` を立てる（法令の解決は残す）。附則（`s<k>`）と別表（`t<k>`）の pid も同じく条までに丸めてから落とす。例外は L7 で条番号から数えた pid（上の L7）と、改正法（`amendingLaw`）の pid と、前置き「旧」「改正前の」「廃止前の」がついた参照の pid（今の本文から消えた条を指すことがあるので、落とさずに残す）。

### 6. 並列の連鎖

参照と参照の間が「、」「及び」「又は」「並びに」「若しくは」「・」「から」「まで」と空白だけでつながっているものを1つの連鎖とする。連鎖の中で法令名のない条項は、連鎖の前の参照の法令を引き継ぐ。項だけ（「第二項」）が来たら、前の参照の条を引き継ぐ。

連鎖を切らないもの（間にあっても連鎖を続ける）:

- 参照の直後の丸括弧書き「（…）」全体（「X法第A条第一項（第N号に係る部分に限る。）、第B条本文、…」「X法第A条第二項（同法第C条において準用する場合を含む。）、第B条第一項第三号」）。
- 参照の直後の「本文」「ただし書」「前段」「後段」「各号」「の規定」（「X法第A条第一項本文並びに第B条」「X法第A条の規定並びに第B条の規定」）。

括弧書きの扱い:

- 括弧を越えて引き継ぐのは、括弧の直前の参照の法令と条（括弧の中に出た参照ではない）。「第A条の規定（Y法第C条の改正規定を除く。）並びに第B条の規定」の「第B条」は、第A条と同じ法令（改正附則の中なら改正法）を引き継ぐ。
- 括弧の中の、法令の手がかりのない項・号・イロハ（「（第N号に係る部分に限る。）」「（ただし書及び第N号を除く。）」「（第M項に限る。）」）は、括弧の直前の参照の法令と条（項まであれば項）を引き継ぐ。括弧の中に法令の手がかり（法令名、「同法」、「法」など）があれば、それに従う。
- 括弧の中が「以下…において「X」という。」「…において同じ。」の形で、「第M項において」「次号及び第N号において」のように有効範囲を示す条項は、今の条・項（自分の法令）を指す（括弧の直前の参照を引き継がない）。
- 「次に掲げるもの（…第N号に掲げるもの…）」のように、「次に掲げる」の後の括弧の中の素の号は、今の条項の号（自分の法令）。前の他法令の参照を引き継がない。

連鎖が切れるのは、句点、上のもの以外の語（「の規定により」「に規定する」の後に名詞が続くなど）、別の法令の手がかりが出たとき。

弱い接続での引き継ぎは、条の有無で確かめる:

- 「の規定、」「の規定並びに」「の規定及び」「本文並びに」「（…）、」のように、「の規定」「本文」や括弧書きをはさんで続く連鎖（強い接続「、」「及び」だけで直接つながる連鎖ではないもの）で、引き継ごうとする法令に、その条がコーパスにない（条までに丸めても `null` になる）とき、次の順で条がある法令を採る: (1) その連鎖が始まる前の文脈の法令（下の 6a の表の行の法令や読替え表の法令、外側の括弧の直前の参照の法令）、(2) 自分の法令。どちらにもなければ引き継ぎのままにする。採った参照は `rule: 'L6-provision-exist'` とし、`stats.json` に件数を出す。
- 「X において準用するY法第A条…の規定、第B条」のように、準用の句の中で出た Y法 は、その句が「の規定、」で閉じたところで連鎖から外す（後ろの「第B条」に Y法 を引き継がない。上の条の有無の確かめで Y法 に第B条がなければなおさら）。
- 改正附則（`supplAmend`）の中でも、連鎖での引き継ぎは素の条の規則（改正法の条にする）より先に効く。括弧の中で始まる連鎖（「（法第A条第一項又は第B条第一項の規定による…）」）も同じ。

### 6a. 表の文脈

表のセル（`inTable: true` の文）は、同じ pid の中で続くセルを1つの表として扱い、表の外の文から次の文脈を受け取る。

- 行の法令のセル: セルの中身が法令の参照1件だけ（法令名、法令番号つきの名前、略称。末尾の「の規定」などはあってよい）のとき、その法令をその表の「行の法令」にし、次の行の法令のセルが出るまで、後ろのセルの法令の手がかりのない条項（L6）はその法令の条項にする（自分の法令にしない）。「法律名の欄・条項の欄」と並ぶ別表の形。
- 読替えの表: 表の直前の文（同じ条項の最後の、表でない文）が「次の表の上欄に掲げるX(の規定)中」「X(の規定)の適用については、次の表の上欄に掲げる同法の規定中」の形なら、X をその表の法令にする。表の見出しのセルが「X(の規定)中読み替える規定」「Xの規定」の形でも同じ。その表の中の法令の手がかりのない条項は X の条項にする（読み替える字句の欄の、カギ括弧の中のものは今までどおり参照にしない）。
- 表の法令よりも、セルの中の手がかり（法令名、略称、「同法」、「この法律」）を先に使う。表の文脈を使った参照は `rule: 'L6-provision-table'`（`flags` は `enumCarry`）とし、行の法令と読替えの表に分けて `stats.json` に件数を出す。

### 7. 種類を決める（参照ごと。REF_KINDS の順に最初に当てはまるもの）

- `basis` 制定の根拠: 部が `enact`。または府省令・規則の本則の最初の文で「…の規定に基づき」の前にある参照。
- `implements` 委任の受け皿: 参照元が政令・府省令・規則・勅令で、参照の直後が「の」「に規定する」を挟んで20字以内に「（政令|内閣府令|省令|主務省令|府令|規則|命令）で定める」が来るもの。例:「法第五条第一項の政令で定める者は」。
- `amend` 改正・廃止: 部が附則系で、参照の直後が「の一部を次のように改正する」「の一部を改正する。」「を廃止する。」（動詞として文を結ぶ形）であるもの。「…改正する法律」「…廃止する政令」のように題名を作る形は `amend` にしない（L5 の「改正法の題名」で別の法令として扱う）。または文が改正の指示（「中「」「を「」と「改める」「加える」「削る」を含む）の中の条項。
- `junyo` 準用: 文の中で、参照より後に「準用する」がある。
- `rei` 例による: 参照の後ろ30字以内に、句点をはさまずに「の例による」がある。
- `exclude` 適用除外: 参照の直後が「の規定(は|を)」で、文の中で参照より後に「適用しない」「適用を除外」がある。
- `term` 定義・用語の借用: 参照の直後が「に規定する」「にいう」「に定める」で、その後に「ところ」が続かない。
- `cite` 引用: 上のどれでもない。
- 読替え: 文が「とあるのは」と「読み替え」を含むとき、その文の参照に `yomikae` のフラグを立てる（種類は変えない）。

## テスト方法

- 単体テスト（vitest、`pipeline/test/extract/`）。規則ごとに最低5件、合計80件以上。期待値は「文、法令ID、pid、期待する参照の一覧（mention、tgtLaw、tgtPid、kind、flags）」の形で `fixtures/*.json` に書く。例文は e-Gov の実際の文から取り、出典の lawId と pid を書く。最低限次を含める:
  - 制定文: 租税特別措置法施行令の「内閣は、租税特別措置法（昭和三十二年法律第二十六号）の規定に基き、及び同法を実施するため、この政令を制定する。」→ 租税特別措置法（`332AC0000000026`）への `basis` が2つ（2つ目は「同法」）。
  - 委任の受け皿: 施行令の「法第○条第○項の政令で定める…」。
  - 略称の有効範囲: 「以下この条において「X」という」が次の条で効かないこと。
  - 括弧の中の略称: 労働基準法施行規則の「金融商品取引法（昭和二十三年法律第二十五号。以下「金商法」という。）第二条第九項」→ 「金融商品取引法（昭和二十三年法律第二十五号」（金融商品取引法、`tgtPid: null`）と「第二条第九項」（金融商品取引法の `m.a2.p9`）の2件。続く「金商法第二十八条第一項」も同じ法令。
  - 範囲: 「第三条から第五条まで」、「第三条乃至第五条」。
  - 並列: 「民法第一条、第二条及び第三条」→ 3つとも民法。「第一項若しくは第二項」。
  - 前N条: 「前二条の規定は」。
  - 準用と読替え: 「第五条の規定は、…について準用する。この場合において、同条中「A」とあるのは「B」と読み替えるものとする。」
  - 例による・適用除外・定義の借用の各1件以上。
  - 改正法由来の附則の「この法律」が改正法を指すこと。
  - カギ括弧の中の「第三条」を拾わないこと。
  - 長い名前の一部を拾わないこと（例: 「民法施行法」の中の「民法」）。
  - 「民法第九十条」のように「第」が続く名前は採ること。「第一条中関税法第三条の改正規定」の「関税法」を採ること。
  - 「この政令は、学校教育法の一部を改正する法律の施行の日から施行する。」→ 学校教育法への参照を作らず、題名全体を `amendingLaw` で1つ。「（〇〇法の一部改正）〇〇法（…号）の一部を次のように改正する。」→ 〇〇法への `amend`。
  - 「同法」の種類合わせ: 「都市計画法第二十九条…都市計画法施行令第三十四条…同法第二十九条」の「同法」が都市計画法を指すこと。同じ文の中で近いほうを採ること。
  - 改正附則の中の「第二条の規定による改正後の〇〇法」の「第二条」が `amendingLaw`、「附則第三条」が同じ改正附則の `s<k>.a3` を指すこと。`s<k>.a3` が載っていない改正附則では `amendingLaw` の `s1.a3`。
  - 「改正法附則第四条第一項」（「改正法」は本文で定義した略称）が1つの参照で、その法令の `s1.a4.p1`。「〇〇法の一部を改正する法律附則第三条第三項」が `amendingLaw` の `s1.a3.p3`。「厚生年金保険法第八十七条第一項及び附則第十七条の十四」の2つ目が厚生年金保険法の `s1.a17_14`。「昭和六十年法律第三十四号附則第五条」が番号で引いた法令の `s1.a5`。
  - 号の細分: 「第一号イ及びロ」で2つ、「第一号ホニ規定スル」で `…i1.i5` まで（`ニ` を読まない）。
  - 次の形を各2件以上。例文はコーパスから探す。ゴールドの文と重ならないかは計画担当がレビューで確かめるので、ゴールドのファイルは見ない。
    - 括弧書きを越える連鎖: 「X法第A条第一項（第N号に係る部分に限る。）、第B条本文、第C条」で3つとも X法。括弧の中の「第N号」は X法の第A条第一項第N号。
    - 括弧の中の参照を引き継がない連鎖: 改正附則の「第A条の規定（Y法第C条の改正規定を除く。）並びに第B条の規定」で、第B条は改正法の `m.aB`。
    - 有効範囲の括弧: 「X法第A条の規定による処分（第M項において「X」という。）」の第M項が今の条の項。
    - 「の規定並びに」「本文並びに」を越える連鎖。
    - 定義の括弧をはさむ法令名と条項: 「X法（以下「法」という。）第A条第B項」で「X法」（`tgtPid: null`）と「第A条第B項」（X法の `m.aA.pB`）の2件。「X法（平成N年法律第M号。以下「法」という。）第A条」で「X法（平成N年法律第M号」と「第A条」の2件。「X法（平成N年法律第M号）第A条」は1件のまま。本則で定義した「法」が制定時の附則と別表でも効くこと。
    - 「同条第四項」「同項第三号」「前条第二項」が1つの参照になり、「同条」の先行詞が他法令ならその法令になること。
    - 法令番号の括弧の中の「同法」が、その番号の法令を指すこと。
    - 「この条」「この項」「この号」「本項」の pid。
    - 抄の改正附則で、第一条・第四条だけが載っているとき、第四条の「前条」が `s<k>.a3`。第一条・第三条だけのとき、第一条の「次条」が `s<k>.a2`。
    - 「新X法第N条」「旧X規則第N条」「改正前のX法」が X（X がこの法令なら `self`）。「…の規定による改正前のX（以下「旧X」という。）」の旧X が X。
    - 「第N条第M項の表第K号イ」が前の条項の続きで1つの参照。
    - 「X法附則の規定」「X法施行令第三編第二章」「X規則第四号様式」が `lawLevelOnly` の1つの参照。
    - 「第九十条中農林中央金庫法第四十六条の三の次に一条を加える改正規定」「同条中中小企業団体の組織に関する法律第百十三条」が採れること。
    - カタカナ書きの文の「…ニ於テX法第A条」「…ヨリX法施行令第A条」。
    - 末尾が法令の種類でない略称（「（以下「対象事業者」という。）」「（以下「特定設備等」という。）」）を法令の略称にしないこと。`oldTitles` の断片（「監督」）が辞書にないこと。
  - 2周目の形（各2件以上。例文はコーパスから探し、ゴールドのファイルは見ない。下の形は説明用で、そのまま例文にしない）:
    - 表の行の法令: 別表で「X法（平成N年法律第M号）」だけのセルの後に「第A条第一項、第B条の規定」のセルが続くとき、第A条・第B条が X法。次に「Y法」だけのセルが来たら、その後は Y法。法令名だけのセルがない表では、素の条項は今までどおり自分の法令。
    - 読替えの表: 表の直前の文が法令 X と「次の表の上欄に掲げる（同法の）規定中」を含むとき、表の中の「第A条第二項」が X法。見出しのセルが「（本文の略称）の規定中読み替える規定」の表も同じ。
    - 定義の文: 定義の条の「「X規則」とは、Y規則（…号）をいう。」の後、本則と別表の「X規則第A条」が Y規則。
    - 範囲つきの定義: 「Y法（…号。同項において「X法」という。）」「（第四項において「X法」という。）」の後の「X法第A条」が Y法。同じ語が JLaw の辞書で別の法令を指していても、本文の定義を採ること。
    - 法令番号の括弧の定義: 「Y規則（昭和N年…省令第M号。以下「X則」という。）」「Y法等の一部を改正する法律（平成N年法律第M号。以下「平成N年改正法」という。）」が記録され、後の「X則第A条」「平成N年改正法附則第B条」が解決されること。
    - 法令の中の予備の定義: ある改正附則で「改正後のX規則（以下「新X規則」という。）」と定義し、別の改正附則（定義の条が抄で載っていない）に「旧X規則第A条第二項」が出るとき、X規則の `m.aA.p2` になること。どこにも手がかりのない「旧Z規則第A条」は、語と条項で1つの `unknown`（後ろの条項だけを改正法の条にしない）。
    - 素の「法」: 本文で「法」を定義した法令で、素の「法」が「の施行」「の規定」「の適用」に続く形（文の始めを含む）が、その法令への参照になること。
    - 「同条」「同項」の先行詞: 括弧の中の他法令の条項を先行詞にする形、連鎖で他法令を引き継いだ条項を先行詞にする形、「同項第N号」「同条第M項」と照応が続く形、の各2件で、どれも他法令のまま。「法第A条第二号に規定する者に係る同条の主務省令で定める事項」の「同条」が 法の `m.aA`（今の条ではない）。
    - 「同表」: 「次の表の左欄の区分に応じ同表の右欄に掲げる率」の「同表」が自分の法令（他法令の条にしない）。「X規則第A条の表第三号…同表第五号」の「同表第五号」が X規則の第A条。
    - 弱い接続の確かめ: 「X法施行令第A条の規定並びに第B条の規定を適用する場合」で、X法施行令に第B条がなく自分の法令にあるとき、第B条は自分の法令。X法施行令に第B条があれば X法施行令のまま。
    - 準用の句で連鎖を切る: 表の行の法令が Z法 のセルで「第A条において準用するY法第C条の規定、第B条」の第B条が Z法。
    - 右の境界: 「…X法施行令、Y法施行令及びZ法施行令の規定は」で Y法施行令・Z法施行令の両方が採れること。「X法又はY法の規定により」も同じ。
    - 別表の行: 「X法別表第二の三の項（同項の下欄…）」で「別表第二の三の項」が X法の `t<k>.i3`、「同項」も同じ。
    - 改正附則の中の連鎖: 改正附則の「（法第A条又は第B条第二項の規定により届け出たものを含む。）」の第B条が 法（改正法の条にしない）。
    - 琉球政府の立法: 「沖縄のX法（千九百N年立法第M号）」で X法への参照を作らず、「第M号」を条項にしないこと。
    - 前置きの範囲: 「Y法第一条の規定による改正前のX法（以下「旧X法」という。）第A条」の1件目の `mention` が「改正前のX法」から始まり（「の規定による」を含まない）、「第A条」が2件目。「廃止前のX法第A条」が X法。
    - 旧X法の pid: 「旧X法第A条の二第五項」で、今の X法に第A条の二がなくても `tgtPid` を残すこと。
    - 「次に掲げるもの（…第一号に掲げるもの）」の第一号が自分の法令の今の条項の号。
- 回帰テスト: `npm run extract -- --law {lawId}` の出力を、民法、地方自治法、租税特別措置法施行令、労働基準法施行規則の4件で `test/extract/snapshots/` に保存し、変化があれば差分を見る。
- 全件を動かしたあと、`stats.json` の規則別・種類別の件数を `report.md`（`data/refs/{snapshotId}/report.md`）にまとめる。
