# M2-02 アトラス v1 の UI

## 目的

## データの読み込み

1. `/data/latest.json` を読み、`dataPath` の下の `manifest.json`、`laws.json`、`law-edges.json`、`continents.json`、`category-flows.json` を並行して取る。`contractVersion` が 1 でなければ、エラー表示（「データの版が合いません」）。
2. Web Worker（`workers/geometry.worker.ts`）で、エッジの曲線の頂点（下の「エッジの束ね」）、型付き配列にした属性、分野の重心を作り、Transferable で返す。
3. 最初の描画ができたら `performance.mark('atlas:first-frame')` を打ち、`window.__atlas.ready = true` にする。
4. 法令を選んだら `refs/{lawId}.json` を取る（同じ法令はキャッシュ）。

## 描画の層（下から順に）

ズームは `fitZoom`（全体が画面に収まるズーム）を基準にする。`minZoom = fitZoom − 1`、`maxZoom = fitZoom + 7`。

1. 大陸: `SolidPolygonLayer`（塗り、分野の色、不透明度 0.08）と `PathLayer`（輪郭、分野の色、不透明度 0.25、1px）。`fitZoom + 3` より拡大したら塗りを 0.04 にする。
2. 分野間の流れ: 全体表示では描かない（分野のラベル位置どうしを結ぶ太い管は、島の上を覆う網になるため）。まとまりか分野にフォーカスしている間だけ、`category-flows.json` のうちフォーカス中の分野が関わる上位12本を、ラベル位置どうしを結ぶ2次ベジエ（中点から垂直に長さの0.2ずらす、20分割）で描く。幅は `sqrt(refs)` に比例させ最大4px、色は参照する側の分野の色、不透明度 0.3。
3. 法令間のエッジ（全部）: Worker で作った曲線の `PathLayer`（binary attributes、`startIndices`）。幅は `0.6 + 0.25 × log2(1 + mainRefs)` px、上限3px。色は、色分けが「分野」なら参照する側の分野の色、「参照の種類」なら `domKind` の色。加算合成（`parameters` で `blendColorOperation: 'add'`、`blendColorSrcFactor: 'src-alpha'`、`blendColorDstFactor: 'one'`）。近い線の層の不透明度は `0.12 × min(4, 2^max(0, Δ − 1))`（Δ ≤ 1 で 0.12、2 で 0.24、2.5 で 0.34、3 以上で 0.48）。拡大すると間引きで画面の中の線が減る（民法を中心に +4 で約1,000本）ので、1本ずつが見える濃さまで上げる。遠い線の層は 0.06 で固定する。加算の結果が白く飽和せず、しかも線が見えること（「見た目の判定（線とラベル）」の P1〜P3）。そのための調整（不透明度、アルファの合成の設定、キャンバスを `--bg` で不透明に塗ること）は担当が選んでよいが、選んだ値を報告に書く。色の合成を普通の重ね塗り（`dst = one-minus-src-alpha`）に替えない（線の多い所が最後に描いた色の不透明な面になるため）。ハブに集まる線が白く飽和するときは、層全体を暗くせず、線ごとの不透明度を「同じ（参照する側の分野、参照される側の分野）の組で描く線の数」の平方根で割って、太い束ほど1本ずつを薄くする（Worker で頂点の色のアルファに入れる。組の線の数は全体表示の重み5以上で数える）。この割り算は分野をまたぐ線だけに使う。同じ分野の中の線は組の線の数が数百になり（中央値145、最大764）、割ると見えなくなるので、割らずに一定の係数（1以下、担当が P1 を守れる値を選ぶ）を掛けるだけにする。`pickable: false`。
   - 色分けが「参照の種類」のときは、`cite`（引用）の線の頂点アルファを他の種類の 0.35 倍にし、`cite` を先に（下に）描く（地図が引用の灰白一色にならないように）。
   - フィルタは GPU で行う: `DataFilterExtension({ filterSize: 4, categorySize: 4 })`。`getFilterValue = [mainRefs, supplRefs, mainRefs + supplRefs, 線の世界座標での長さ（端点間の直線距離）]`。`getFilterCategory = [domKind, srcの法令種別, tgtの法令種別, intraFamily]`。部の切り替えは `filterRange` で表す（本則のみ: 1番目を `[最小の重み, ∞]`、他は `[−∞, ∞]`。附則のみ: 2番目。すべて: 3番目）。
   - ズームの間引き（LOD）: ズームするほど「短い線を足し、長い線を減らす」。同じ binary attributes を使う2つの層に分ける（属性はどちらも1回だけ作り、パンとズームでは `filterRange` だけを変える）。`Δ = zoom − fitZoom`、`Lz = 画面の対角線の世界座標での長さ × 0.6` とする。
     - 近い線の層: 長さ ≤ `Lz`、重みの下限 `max(1, 5 − 2Δ)`（小数は切り上げ、`Δ ≤ 0` では 5）。`Δ ≥ 3` では、この層を法令の点の上（ラベルと選択の層の下）に描く。点は世界座標で大きくなり、島の中で隙間なく並ぶので、点の下に描くと近い線が隠れるため。
     - 遠い線の層: 長さ > `Lz`、重みの下限 `20 × 4^(Δ − 1)`（Δ = 1 で 20、2 で 80、2.5 で 160、3 で 320）。層の不透明度は 0.06 で固定（上の3番目）。拡大した画面を長い線が雨のように横切らないようにするため（重み28以上の線だけでも約4,000本ある）。
     - `Δ ≤ 0.5` では `Lz` を ∞ として、近い線の層だけを使う（全体表示では重み5以上をすべて描く）。
4. 選んだ法令（またはホバー中の法令）のエッジ: その法令の入出力のエッジだけの `PathLayer`。参照の種類の色で、頂点ごとの色を使い、参照する側の端で不透明度 0.25、参照される側の端で 1.0 にする（向きが分かるように）。幅 1.5px（選択中は 2px）。`pickable: true`。ホバーでツールチップ（「A → B　準用 12・引用 3」）、クリックでエッジの詳細を開く。
   - 描く順は、`cite`（引用）を一番下にし、`cite` は幅 1px・不透明度の上限 0.4 にする。その上に `cite` 以外を種類ごとに重ねる（放射が引用の灰白一色にならないように）。
   - ほかのエッジの層（近い線・遠い線・分野間の流れ）は不透明度を 0.15 倍にする。
   - 隣の法令のうち言及数の上位15件は、`prRank` の条件に関係なく名前を出す（衝突の回避は効かせる）。
5. 法令のノード: `ScatterplotLayer`。半径は `r`（ワールド単位）、`radiusMinPixels: 1.2`、`radiusMaxPixels: 48`。分野の色で塗る。ゴースト（`status = repealed`）は塗らずに灰色の輪郭だけ。`DataFilterExtension({ categorySize: 2 })` で法令種別と状態のフィルタ。選択中は、隣接しない法令の不透明度を 0.25 にする（`updateTriggers` で塗りの色だけ更新）。`pickable: true`。
6. 選択の輪: 選んだ法令に、`--accent` の 2px の輪。
7. ラベル: `TextLayer`。`characterSet: 'auto'`、`fontFamily` は Noto Sans JP（`document.fonts.load` で読み込みを待ってから層を作る）。
   - まとまりの名前: `fitZoom + 0.75` 未満でだけ、16px で出す（全体表示で見える名前は13個だけ）。
   - 分野の名前: `fitZoom + 0.75` 以上 `fitZoom + 3` 未満で、`labelPos` に 14px、500、分野の色を明るくしたもの。まとまりの名前と同時には出さない。分野の名前どうしにも `CollisionFilterExtension` を効かせる（優先度は法令数の多い順）。
   - 法令の名前: `label` を 11px、`--text`。`CollisionFilterExtension` で重なりを避け、優先度は PageRank が高い順（`getCollisionPriority = −prRank`）。さらに `prRank ≤ 150 × 4^(zoom − fitZoom)` のものだけ出す（`DataFilterExtension` の範囲をズームに合わせて変える）。
   - 文字に背景の色の縁取り（`outlineWidth: 2`、`outlineColor: --bg`）。

## エッジの束ね（Worker）

- 分野の重心 `C_k` は、その分野の法令の位置の平均。
- 分野をまたぐエッジ（s → t）: 制御点を `[P_s, C_cs, C_ct, P_t]` とし、β = 0.8 でまっすぐな線に寄せる（`Q_i = β·P_i + (1−β)·(P_s + (i/3)(P_t − P_s))`）。`Q` を制御点とする3次ベジエを16分割（17点）。
- 同じ分野の中のエッジ: 2次ベジエで、中点から進行方向の左に長さの0.15ずらした点を制御点にする（9点）。左に曲がるので、向きが曲がり方で分かる。
- 出力: `Float32Array`（x, y）と `Uint32Array`（startIndices）。約8万本で400ms以内。

## 操作

- ホバー（法令）: すぐにその法令のエッジを強調する（動きなし）。ツールチップ（表示名、種別、分野、参照する/される法令の数）は最初だけ 250ms 待って出し、その後 600ms 以内に別の法令に移ったら待たずに出す（2回目以降は動きなし）。
- クリック（法令）: 選択し、詳細パネルを開き、カメラをその法令に寄せる（今のズームが `fitZoom + 2` 未満なら `+2.5` まで寄せる）。
- クリック（何もないところ）: 選択を外す。
- ダブルクリック: その場所に1段拡大。
- キーボード: `/` か ⌘K / Ctrl+K で検索欄に移る。Esc は、検索の候補を閉じる → エッジの選択を外す → 法令の選択を外す、の順に1つずつ。地図にフォーカスがあるとき、矢印キーで80px移動、`+` `−` で拡大縮小、`0` で全体表示。キーボードによる移動と拡大縮小は動かさずに即座に切り替える。
- 戻る・進む: 選択の変化は履歴に積む（`pushState`）。ブラウザの戻るで前の選択に戻る。

## 詳細パネル（法令）

- 見出し: 法令名（明朝 20px 600）、その下に法令番号・種別・分野（色の点）・公布日。e-Gov の法令ページへのリンク（`https://laws.e-gov.go.jp/law/{lawId}`、新しいタブ）。ゴーストは「廃止された法令」と表示する。
- 数字の行（等幅数字）: 条の数、この法令を参照する法令の数、この法令が参照する法令の数、PageRank の順位（「全体で {prRank} 位」）、委任の言い回しの数、参照してくる分野の数。
- 法令ファミリー: 親（あれば）と、子（自分を親とする法令）を並べる。クリックでその法令へ。
- 「この法令を参照している法令」と「この法令が参照している法令」の2つのタブ。各行は、相手の表示名、言及数、種類の内訳の細い帯（種類の色）。言及数の多い順。最初は30行、「さらに表示」で30行ずつ。行のクリックでその法令を選ぶ。行の右の「箇所」ボタンで、その相手との参照箇所の一覧を開く。
- 参照箇所の一覧: 1行ごとに「第三条第一項 → 第九十条」のような位置（pid を日本語に直したもの）と種類。行をクリックすると、その下に条文を出す。本則なら API から版IDを固定して取り（00 の「条文本文の取得」）、言及を強調する。附則などは `ctx` を出し、e-Gov へのリンクを付ける。取得中は灰色の行の骨組みを出す。失敗したら「e-Gov から本文を取れませんでした」とリンクを出す。
- 本文は明朝 15px、行の高さ 1.9。強調は背景 `rgba(242,184,75,0.22)` と下線 2px `--kind-basis`。

## 詳細パネル（エッジ）

- 見出し: 「A → B」（両方の表示名。クリックでその法令へ）。本則系と附則系の言及数、種類ごとの数。
- 参照箇所の一覧（上と同じ部品）。データは A の `refs` の `out` から B の行を取る。

## 検索

- 対象: `title`、`label`、`aliases`、`kana`、`numNorm`。
- 正規化: NFKC、空白の除去、カタカナをひらがなに、漢数字を算用数字に（法令番号の照合用）。
- 順位: 完全一致（名前・略称・法令番号）100 → 名前・略称の前方一致 80 → 読みの前方一致 70 → 名前の部分一致 50 → 読みの部分一致 40。同点なら `prRank` の小さい順。上位20件。
- 候補の各行: 表示名、種別、分野の色の点、法令番号（小さく）。一致した部分を太字にする。
- 操作: 入力ごとに即座に候補を更新（動きなし）。↑↓で選び、Enter で選択（カメラ移動と詳細パネル）。
- 例（受け入れテストで使う）: 「みんぽう」→ 1位が民法。「個人情報保護法」→ 個人情報の保護に関する法律が上位3位以内。「平成15年法律第57号」→ 個人情報の保護に関する法律が1位。

## フィルタ（Popover）

- 参照の種類: 8種のチェック。初期値は `amend` 以外すべて。
- 部: 「本則のみ」（初期値）、「附則のみ」、「すべて」。
- 法令種別: 7種のチェック。初期値はすべて。エッジは両端が表示されているものだけ。
- 最小の言及数: 1〜20 のスライダー（初期値1）。
- 「同じファミリーの中の参照を隠す」（初期値オフ）。
- 変更はすぐに地図に反映する（GPU のフィルタなので属性は作り直さない）。表示中のエッジの数をフィルタの下に出す（`window.__atlas.visibleEdgeCount` と同じ値。CPU で数える）。

## URL の状態

- `law`（lawId）、`edge`（`{srcLawId}~{tgtLawId}`）、`kinds`（種類のIDをカンマで。初期値なら省く）、`parts`（`main`/`suppl`/`all`）、`types`、`minRefs`、`color`（`category`/`kind`）、`focus`（まとまりか分野のID）、`v`（カメラ `x,y,zoom`。x と y は小数0桁、zoom は2桁）。
- 選択の変化は `pushState`、カメラの変化は 400ms 待ってから `replaceState`。
- URL を開いたときは、その状態を復元する（オープニングの演出はしない）。

## 動きの決まり（emil-design-eng による）

- イージングのトークン: `--ease-out: cubic-bezier(0.23, 1, 0.32, 1)`、`--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1)`、`--ease-drawer: cubic-bezier(0.32, 0.72, 0, 1)`。`ease-in` は使わない。
- 何度も使う操作は動かさない: 検索欄の開閉、候補の更新、ホバーの強調、フィルタの切り替え、キーボードによる操作。
- カメラの移動（クリックや検索の Enter で法令に寄るとき）: 位置が変わるので `--ease-in-out` 相当（deck.gl の `LinearInterpolator` と `transitionEasing` に同じ曲線）。時間は `clamp(220 + 90 × |Δzoom| + 0.15 × 画面上の移動px, 240, 520)` ms。ユーザーの操作で中断する（`TRANSITION_EVENTS.BREAK`）。
- 詳細パネル: 開くとき `transform: translateX(100%)` → `0` を 260ms `--ease-drawer`。閉じるとき 180ms `--ease-out`（閉じる方を速く）。開いたまま別の法令に替えるときは滑らせず、中身を 160ms で `opacity 0.6 → 1` と `filter: blur(2px) → 0` にする。モバイルのシートは `translateY(100%)` から同じ時間。下に払ったら、速度が 0.11 px/ms を超えるか、高さの30%以上動いたら閉じる。
- Popover（フィルタ）: 押したボタンを起点に（`transform-origin: var(--transform-origin)`）、`scale(0.97)` と `opacity: 0` から 160ms `--ease-out`。閉じるのは 120ms。
- ツールチップ: 最初は 120ms の `opacity` だけ。2回目以降は動きなし（`data-instant`）。
- 押せるもの: `:active` で `transform: scale(0.97)`、`transition: transform 160ms var(--ease-out)`。
- ホバーの見た目の変化は `@media (hover: hover) and (pointer: fine)` の中だけに書く。
- 動かすのは `transform` と `opacity`（と、中身の差し替えの `filter`）だけ。`transition: all` は使わない。`scale(0)` から出さない。UI の動きは 300ms 以下（カメラ移動とオープニングを除く）。
- オープニング（初回だけ。URL に状態がなく、`localStorage` に見た記録がないとき）: 大陸をまとまりごとに 60ms ずつずらして、400ms `--ease-out` で `opacity 0 → 1`（13まとまりで全体約1.2秒）。その間も操作でき、何か操作したらすぐに最後の状態にする。
- `prefers-reduced-motion: reduce` のとき: カメラは移動せず切り替え、パネルとシートは滑らせず 150ms の `opacity` だけ、オープニングはしない。

## 仮データ

- `web/scripts/make-mock-data.ts`（`npm run mock`）。出力は `data/mock/mock-20261008/` と `public/data/mock-20261008/`、`public/data/latest.json`。
- 法令のメタデータは本物を使う: `https://laws.e-gov.go.jp/api/2/laws?repeal_status=None&limit=1000&offset=…` から法令名・読み・略称・法令番号・種別・分野・版ID。
- 位置: 分野ごとに、円周上に置いた中心のまわりの正規分布（標準偏差は法令数の平方根に比例）。色と分野のまとまりは m2-01 の規則どおり。
- エッジ: 約8万本。70%は同じ分野の中。被参照は優先的選択で偏らせる。種類の割合は cite 70%、term 8%、junyo 8%、implements 6%、basis 3%、rei 2%、exclude 2%、amend 1%。
- `refs` は PageRank 上位300法令の分だけ作る。`mention` は「{相手の法令名}第{N}条」、`srcPid` は `m.a{N}.p1#1`。
- 大陸は d3-contour で作る（m2-01 と同じ手順を簡単にしたものでよい）。
- `manifest.isMock: true`。画面の左上に「仮データ」と小さく出す。

## 性能の目安

## 見た目の判定（線とラベル）

m2-01 の「3件目との境目」で、この仕様に回したもの（束ね、ズームの間引き、線の不透明度・太さ・色、ラベル、deck.gl の設定）の合否を、画面の画像で決める。担当は数値（P1〜P3）の結果だけを書く。U1〜U8 は coordinator が判定するので、担当は自分で合格にしない。

### 撮る画像

- `scripts/capture-m3.ts` で撮り、`media/m3/` に置く。ビューポートは 1440×900、`deviceScaleFactor: 2` で、PNG が 2880×1800 になっていること。オープニングはしない（`localStorage` に見た記録を入れる）。
- `window.__atlas.edgesReady === true` を待ってから、さらに2フレーム待って撮る。`edgesReady` は、Worker の曲線ができてエッジの層が描かれた最初のフレームで true にする（`ready` は今までどおり最初のフレーム）。「地図を準備しています…」が出ている画像は無効。
- 撮る6枚:
  - `ui-overview.png`: `fitZoom`、選択なし、色分けは「分野」。
  - `ui-overview-kind.png`: 上と同じで、色分けは「参照の種類」。
  - `ui-zoomed.png`: 民法の位置を中心に `fitZoom + 2.5`、選択なし。
  - `ui-zoomed-deep.png`: 民法の位置を中心に `fitZoom + 4`、選択なし。
  - `ui-selected-minpo.png`: 民法を選び、カメラは全体表示（`fitZoom`）。
  - `ui-selected-minpo-zoomed.png`: 民法を選び、民法を中心に `fitZoom + 2.5`。

### 数値（担当が測って書く）

`scripts/check-screens.ts` で6枚を測り、`media/m3/screens-check.json` に出す。地図の領域は、画面の上下80px と左右200px を除いた矩形とする（詳細パネルが出ているときは、右端をパネルの左端から20px内側にする。px は CSS の値）。

- P1 白飛び: R、G、B がすべて235以上の画素が、地図の領域の0.5%以下（6枚すべて）。
- P2 海の暗さ: 輝度（0.2126R + 0.7152G + 0.0722B）の中央値が40以下（6枚すべて。背景 `--bg` は約14）。
- P3 線が描かれていること: `ui-overview` と `ui-overview-kind` の地図の領域を画素ごとに比べ、R、G、B の差の絶対値の合計が15を超える画素が3%以上ある（色分けを替えて変わるのは法令間のエッジだけなので、差がなければエッジが描かれていない）。

### 画像で判定すること（coordinator）

- U1（`ui-overview`）: 島（大陸と法令の点）が画面の主役で、線より先に目に入る。島の上を太い管や一様な網が覆っていない。1つの島に集まる扇形の線が、途中にあるほかの島を覆い隠していない。分野をまたぐ線は、島から島への流れ（束）として見え、地図の全体に同じ明るさで広がる霧になっていない。名前はまとまりの13個だけで、重なりも欠けもなく、文字が正しく組まれている（「・」の前後に不自然な空きがない）。
- U2（`ui-overview-kind`）: 引用（灰白）以外の種類の色が地図の上で見分けられ、全体が灰白一色になっていない。
- U3（`ui-zoomed`）: 背景が暗いまま。画面の中の島どうしを結ぶ短い線が主で、画面を端から端まで横切る線は少なく、暗い。法令名が30以上読め、重なっていない。分野の名前が島の上にある。
- U4（`ui-zoomed-deep`）: 画面の中にある法令どうしの近い線（同じ分野の中の左に曲がる線を含む）が、点の上でも隙間でも1本ずつ見分けられ、端までたどれる。両端とも画面の外にある長い線は少なく、暗い。法令名が60以上読め、重なっていない。
- U5（`ui-selected-minpo`）: 民法の線が種類の色で分かれ、引用の灰白一色の放射になっていない。向き（参照する側の端が薄い）が分かる。ほかの線は選んだ線より明らかに暗い。隣でない法令は暗く、選んだ法令自身と隣の上位の法令名が出ている。
- U6（`ui-selected-minpo-zoomed`）: U5 と同じことが拡大でも成り立ち、近くの相手の名前と線の端が対応づけられる。
- U7（画面の部品、6枚すべて）: 地図の点や法令名が、ロゴ・副題・検索欄・出典の文字に重ならない（その後ろに `--bg` の帯やぼかしを敷くか、そこにラベルを置かない）。出典は1行に収まる（入りきらない分は省略し、全文は `/about`）。読み込み中の表示は準備ができたら消え、出典と重ならない。詳細パネルのタブの文字が折り返さない。数字の行の順位は「全体で {prRank} 位」と書く。
- U8（作品としての質）: 1枚の地図で、(a) 全体では分野の島と、島どうしの太い流れ、(b) 拡大では法令の名前と個々の線、(c) 選択では1つの法令の参照の種類と向き、が説明なしに読み取れる。どの画像にも、白飛び、一様な霧、文字の重なり、はみ出しがない。(a) と (c) は、分野ごとに分かれた図で種類のない線しか出ない lawvis では見えないもので、ここが lawvis をはっきり上回る点になる。

## 受け入れ条件

- 「見た目の判定（線とラベル）」の6枚と `screens-check.json` が `media/m3/` にあり、P1〜P3 を満たし、U1〜U8 を coordinator が満たすと判断する。
- 地図に50分野の大陸と全法令のノードが出る。左上の件数が manifest と一致する。
- 検索の3つの例が上のとおりに動く。
- 法令を選ぶと、詳細パネルの数字が `laws.json` と一致し、参照している/されている法令の一覧が言及数の多い順に出る。本物のデータで、参照箇所の本則の条文が e-Gov から1秒以内に出て、言及が強調される（民法を参照する法令から3件で確かめる）。
- フィルタを変えると表示中のエッジの数が変わり、URL に反映され、再読み込みで戻る。
- キーボードの操作がすべて動き、キーボードの操作では何も動かない。
- `prefers-reduced-motion` でカメラが移動しない。
- モバイルの幅で、シートが開き、払って閉じられる。
- `npm run lint:motion` が通る（下の検査）。
- Lighthouse のアクセシビリティが 90 以上。検索欄、ボタン、タブ、一覧に名前とロールがある。選択が変わったら `aria-live="polite"` の領域で法令名を読み上げる。
- 画面の画像 `media/m2/ui-overview.png`、`ui-selected-minpo.png`、`ui-mobile.png` を store に置く。

## テスト方法

- 単体（vitest）: 検索の正規化と順位、URL の状態の往復、束ねの頂点（端点が法令の位置と一致すること、頂点の数）、ズームの間引きの範囲（`Δ` ごとの近い線・遠い線の長さと重みの下限が上の式どおりであること）、pid を日本語に直す関数（「m.a398_2.p1.i2」→「第三百九十八条の二第一項第二号」）、本文の中の言及の探し方。
- E2E（Playwright、`next build` と `next start`、仮データ）: 読み込み（`window.__atlas.ready` が5秒以内に true）、検索の3例、Enter で URL に `law=` が付く、再読み込みでパネルが戻る、フィルタで `visibleEdgeCount` が変わる、Esc の順番、`reducedMotion: 'reduce'` で `window.__atlas.lastTransitionMs === 0`、幅390pxでシート。
- 動きの検査 `npm run lint:motion`（スクリプトを自作）: CSS と TSX に `transition: all`、`transition-all`、`scale(0)`、`ease-in`（`ease-in-out` は除く）があれば失敗。`@media (hover: hover) and (pointer: fine)` の外に `:hover` があれば失敗。
- 公開URLでの同じ E2E（m2-03）。
